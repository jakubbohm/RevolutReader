# Testing

- **Tests are written before the code, by the test-writer;** the implementer never edits tests (except acceptance `Drivers/` in wiring and close, and `RevolutReader.IntegrationTests/Wiring/`). Implementation runs through `/tdd-apply`; a tooling-only change (`skip_specs: true`, e.g. CI) has nothing to test first and is applied directly with `/opsx:apply`. A code review's findings are triaged and fixed with `/triage-review <PR>`, with the same roles: the test-writer writes the guard test that reproduces a confirmed finding, the implementer makes it pass; a refuted finding is declined only with evidence; a fix that changes a spec's behaviour goes to the user.
- **Every OpenSpec scenario has exactly one claim:** `[Scenario("<capability>", "<exact scenario name>")]` on an API acceptance test, a `scenario("<capability>", "<exact scenario name>", …)` Vitest test for browser-only rules (string literals, in a `*.test.ts(x)` file; any other `scenario(` call is reported as unreadable), or a row in `tests/manual-scenarios.md`. The traceability test fails the build otherwise. It reads the main specs with each active change's delta applied per requirement and ignores `openspec/changes/archive/`.
- **Acceptance test cases (`Scenarios/`) use only the DSL, in domain language** — no HTTP, status codes, IDs or selectors. Only `Drivers/` knows HTTP. A port with its own capability (the bank adapter, `bank-reads`) is driven through the port itself: its driver takes it from the test's app copy (`Services`). Changing a test case is a spec change and needs the user's approval.
- **Behavioural assertions only:** outcomes through public interfaces, never internal calls or private state. Shouldly; hand-written in-memory fakes, no mocking framework; no snapshot testing.
- **A new test must fail at runtime** (a `NotImplementedException` stub or an assertion), never only at compile time.
- **The app runs inside the test process, one copy per test, in environment `Production`** (base `appsettings.json`); structural checks on the running app (the anonymous-endpoint allowlist) live in the acceptance project's `Conventions/`; Enable Banking is a WireMock.Net fake server, and every app copy gets its settings (`Drivers/FakeBank`: its address, made-up ids, a key generated per run, a 5 s timeout, a zero retry wait, since the retries wait on the fake clock; since C9a it can hold its next balance answer, so a burst of account checks is lined up by holding the bank and waiting for the queue's `CallersWaiting`, never by waiting real time); since C9a each app copy also gets a check key of its own (`Drivers/AccountCheckDriver`), and the check is called through its endpoint, as the phone does; since C8a the push services are a WireMock.Net fake too (`Drivers/FakePushService`: its origin as a loopback known push service, a VAPID pair made up per run and a message key per test), checking each push's token and headers and decrypting it with the tests' own RFC 8291 code, never the library's; a `Drivers/TestDevice` plays the phone; both are the test-writer's, with self-tests in `HarnessSelfTests/`; the frontend's push stand-ins are `src/test/push.ts` and, since C8b, the service worker's side `src/test/serviceWorker.ts` (`listenForPushes` tested as plain functions; since c016 its `fetch` goes to the fake server), with the remembered "Teď ne" in `localStorage`, emptied with the phone; since c017 the Czech National Bank's rates API is a WireMock.Net fake too (`Drivers/FakeCnb`: its loopback address and a 2 s limit for every app copy; the CNB's real answer captured 2026-11-21, `Drivers/CnbDaily.json`, with the euro's rate and day replaced, by default 25.125 for the clock's date; a test sets a rate and day, a server error or no answer in time, and counts its requests), so no test reaches the real CNB; since c016 every app copy's log lines are captured with their structured values (`Drivers/CapturedLogEvents`), read by a scenario whose outcome shows only in the telemetry (push-arrivals' `PushArrived` lines); the clock is `FakeTimeProvider`, started at the real current time; sign-in runs the real handlers against a fake Microsoft (`Drivers/FakeMicrosoft`: discovery, keys and token endpoint on WireMock.Net, ID tokens signed with a key generated per run, the allowlist `lucie@example.com,petr@example.com`, Petr since C8a), walked by a test browser on `https://localhost` (`Drivers/SignInDriver`); the allowlist steps check the app copy's list rather than set it; the web root is a stand-in page folder (`Drivers/StandInPages/`), never the frontend build; storage is real, Azurite in one Testcontainers container per test session (image pinned to `mcr.microsoft.com/azure-storage/azurite:3.37.0`), with a table of each app copy's own for every store, `FirstSeenTimes` among them since c018 (`Drivers/AzuriteStorage`, written as host settings); scenario dates are relative to the clock (`Drivers/ScenarioCalendar`: the scenario's today, named with `TodayIs`, is the clock's today, and every other date keeps its distance in days; since c017 `TodayIsAt(day, utcTime)` moves the clock to the coming day of `day`'s weekday at that UTC time, after signing in, for a rule that depends on the weekday; since c018 `TimeIs(utcTime)` moves it forward to a UTC time of the scenario's today, and the instants the app answers, a transaction's `seenAt`, are shifted back like its dates, `FromClock(DateTimeOffset)`). No test needs a real secret.
- **Fake servers listen on loopback only:** every WireMock.Net server starts through `LoopbackWireMock.Start` (`Drivers/`, linked into the integration project), on `127.0.0.1` at a free port; WireMock.Net's own start methods are banned (`BannedSymbols.txt`). One listening on every interface brings up Windows Defender Firewall's admin prompt in every worktree.
- **A port with an in-memory fake has contract tests:** an abstract class written only against the port, with one `[InheritsTests]` subclass for the fake (the unit tests' own file, compiled into the integration project as a link) and one for the real adapter (the transaction store's and, since C8a, the push device store's, on Azurite).
- **Frontend scenarios that wait or store** run on the test clock (`src/test/clock.ts`: `startTestClock()`, then `timePasses(ms)` and `getBy…`/`queryBy…`, never `findBy…`/`waitFor`; taps through `userOnTheTestClock()`), with `fake-indexeddb` as the phone's storage, emptied before every test, and the fake server's answers in order, delays (`after`), abort, offline and leaving the app (`src/test/server.ts`).
- **Fake bank responses are copied from Mock ASPSP captures** (`spikes/enable-banking-mock/evidence/`) or, when the mock cannot produce them, written from the API reference with a comment saying so. **Never real account data** in any test or fixture.
- **No automatic re-runs** of failing tests; a flaky test is fixed or deleted. Docker-dependent tests stop with a message when Docker is not running, never skip silently; since C7b `dotnet test` needs Docker (Azurite).
- **The triage scripts' tests sit next to them** as `*.test.mjs` in `.claude/skills/triage-review/scripts/`, run with Node's own runner (`node --test`): only their pure parts, on made-up objects, never calling `gh` or the network; CI runs them ([testing.md § Where tests live](../../docs/conventions/testing.md#where-tests-live)). The .NET and Vitest tooling above (Shouldly, the DSL, the drivers and fakes, Azurite, the test clock) does not apply to them.
- **tasks.md is the test list:** groups `[acceptance]` → `[unit]` → `[integration]` → `[wiring]` → `[close]`, one behaviour per task, never a "write tests" task. A change of more than 3 scenarios, sliced per scenario, suggests its chapters (runs of slices, each with a fresh pair of agents in `/tdd-apply`) in a short paragraph before group 1 ([testing.md § Task groups](../../docs/conventions/testing.md#task-groups)). A tooling-only change's groups are named after its work instead.
