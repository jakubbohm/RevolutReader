# Testing

- **Tests are written before the code, by the test-writer;** the implementer never edits tests (except acceptance `Drivers/` in wiring and close, and `RevolutReader.IntegrationTests/Wiring/`). Implementation runs through `/tdd-apply`; a tooling-only change (`skip_specs: true`, e.g. CI) has nothing to test first and is applied directly with `/opsx:apply`. A code review's findings are triaged and fixed with `/triage-review <PR>`, with the same roles: the test-writer writes the guard test that reproduces a confirmed finding, the implementer makes it pass; a refuted finding is declined only with evidence; a fix that changes a spec's behaviour goes to the user.
- **Every OpenSpec scenario has exactly one claim:** `[Scenario("<capability>", "<exact scenario name>")]` on an API acceptance test, a `scenario("<capability>", "<exact scenario name>", …)` Vitest test for browser-only rules (string literals, in a `*.test.ts(x)` file; any other `scenario(` call is reported as unreadable), or a row in `tests/manual-scenarios.md`. The traceability test fails the build otherwise. It reads the main specs with each active change's delta applied per requirement and ignores `openspec/changes/archive/`.
- **Acceptance test cases (`Scenarios/`) use only the DSL, in domain language** — no HTTP, status codes, IDs or selectors. Only `Drivers/` knows HTTP. A port with its own capability (the bank adapter, `bank-reads`) is driven through the port itself: its driver takes it from the test's app copy (`Services`). Changing a test case is a spec change and needs the user's approval.
- **Behavioural assertions only:** outcomes through public interfaces, never internal calls or private state. Shouldly; hand-written in-memory fakes, no mocking framework; no snapshot testing.
- **A new test must fail at runtime** (a `NotImplementedException` stub or an assertion), never only at compile time.
- **The app runs inside the test process, one copy per test, in environment `Production`** (base `appsettings.json`); structural checks on the running app (the anonymous-endpoint allowlist) live in the acceptance project's `Conventions/`; Enable Banking is a WireMock.Net fake server, and every app copy gets its settings (`Drivers/FakeBank`: its address, made-up ids, a key generated per run, a 5 s timeout, a zero retry wait, since the retries wait on the fake clock); the clock is `FakeTimeProvider`, started at the real current time; sign-in runs the real handlers against a fake Microsoft (`Drivers/FakeMicrosoft`: discovery, keys and token endpoint on WireMock.Net, ID tokens signed with a key generated per run, the allowlist `lucie@example.com`), walked by a test browser on `https://localhost` (`Drivers/SignInDriver`); the allowlist steps check the app copy's list rather than set it; the web root is a stand-in page folder (`Drivers/StandInPages/`), never the frontend build; storage is real, Azurite in one Testcontainers container per test session (image pinned to `mcr.microsoft.com/azure-storage/azurite:3.37.0`), with a table of each app copy's own (`Drivers/AzuriteStorage`, written as host settings); scenario dates are relative to the clock (`Drivers/ScenarioCalendar`: the scenario's today, named with `TodayIs`, is the clock's today, and every other date keeps its distance in days). No test needs a real secret.
- **A port with an in-memory fake has contract tests:** an abstract class written only against the port, with one `[InheritsTests]` subclass for the fake (the unit tests' own file, compiled into the integration project as a link) and one for the real adapter (the transaction store's on Azurite).
- **Frontend scenarios that wait or store** run on the test clock (`src/test/clock.ts`: `startTestClock()`, then `timePasses(ms)` and `getBy…`/`queryBy…`, never `findBy…`/`waitFor`; taps through `userOnTheTestClock()`), with `fake-indexeddb` as the phone's storage, emptied before every test, and the fake server's answers in order, delays (`after`), abort, offline and leaving the app (`src/test/server.ts`).
- **Fake bank responses are copied from Mock ASPSP captures** (`spikes/enable-banking-mock/evidence/`) or, when the mock cannot produce them, written from the API reference with a comment saying so. **Never real account data** in any test or fixture.
- **No automatic re-runs** of failing tests; a flaky test is fixed or deleted. Docker-dependent tests stop with a message when Docker is not running, never skip silently; since C7b `dotnet test` needs Docker (Azurite).
- **tasks.md is the test list:** groups `[acceptance]` → `[unit]` → `[integration]` → `[wiring]` → `[close]`, one behaviour per task, never a "write tests" task. A tooling-only change's groups are named after its work instead.
