Nothing may appear outside the owner's own repository without the owner's explicit go, and that includes the "mentioned this" backlink GitHub adds by itself to another repository's issue when an issue, PR body, comment or pushed commit message here names it as `owner/repo#123` or as a `github.com/owner/repo/issues/123` link. In GitHub-published text, name upstream issues with a `https://redirect.github.com/owner/repo/issues/123` link (GitHub Docs, "Avoiding backlinks to linked references"), or in words with no link. Repository files (code comments, docs) are not scanned and may keep the plain form. A squash-merge message is published text too.

**Why:** on the first flaky-tests issue (number 68) and its PR (number 94), 2026-11-21, the findings comment and the PR body named dotnet/runtime#110917, dotnet/runtime#135978 and App-vNext/Polly#2412 in the plain form. GitHub put 5 backlinks with the owner's name on those upstream issues. The owner: "I don't want to publish anything outside of my repo without my explicit approval!!!" Editing the text does not remove a backlink (confirmed 2026-11-22: both texts rewritten to redirect.github.com links, all 5 stayed). Then the owner had both recreated (issue #97, PR #98) and the originals removed. Confirmed 2026-11-22: **deleting the issue removes its backlinks** (its 2 vanished at once); **a pull request cannot be deleted** (the API has `deleteIssue` but no pull-request delete; only GitHub Support can), so PR 94 was closed, its title set to "Closed", its description and comments deleted, its branch deleted, and its 3 backlinks stay, showing that bare closed PR, until GitHub Support acts. Copies and links must never name the original (a mention of PR 94 would put a link to the copy on its page). It happened anyway on 2026-11-22: a `/code-review` comment on #98 named "PR #94", GitHub added "mentioned this pull request in #98" to PR 94 a second later, and **deleting the comment did not remove it** (re-checked through the timeline API after the delete). The only removals known: deleting the issue that holds the text, or GitHub Support. Commit messages that name an issue in the plain form are rewritten before a new push, since a re-pushed or squash-merged message can link again.

**How to apply:** before posting or editing any issue, PR, comment, review reply or commit message that will be pushed, scan it for `[\w.-]+/[\w.-]+#\d+`, `github.com/<other owner>/.../(issues|pull)/\d+` and `#94` (the retired PR) and rewrite each one; the triage-review scripts check their own texts (findings, replies, the summary) and refuse such a reference, everything else stays a check by hand (mechanical enforcement: issue #101). Delegated agents that post (code review, triage) get the same rule in their brief. Related: [[public-vs-private-personal-data]], [[decisions-one-by-one]].
